# 第 2 课：真实网页就绪、问题建模和工具反馈

## 这一步在整体中的位置

模型自主选择工具的循环已经运行在 LangGraph 中。这次修的是循环两侧的基础设施：模型开始前能否观察网页，以及观察、校验、执行失败后是否得到可靠反馈。只有这两侧可靠，模型的决策才有实际作用。

## 1. 网页可见，不代表浏览器宣布加载结束

此次招聘页的表单已经显示，但主文档请求出现 `ERR_INCOMPLETE_CHUNKED_ENCODING`，`document.readyState` 长时间保持 `loading`。Chrome 的脚本注入默认等待页面达到 `document_idle`。因此扩展可以显示“正在运行”，却一直没有进入观察或模型调用。

修复分两部分：

- 每次绑定、观察和执行都使用 `injectImmediately: true`，允许读取已经出现的 DOM。
- 启动的文档绑定、服务连接和首次响应分别有日志、停止信号与等待上限，失败时给出具体阶段。

立即注入不会证明整个页面已经就绪。执行器仍绑定启动时的 `documentId`；模型等待后再观察一次，结构变化使旧计划失效，刷新和跳转使旧文档停止。它读取当时已出现的表单，不把后续变化当成稳定事实。

Chrome 官方说明：[chrome.scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)，见 `injectImmediately` 和默认 `document_idle` 行为。

## 2. 一个控件元素不一定是一个问题

原生单选题常由多个 `input[type=radio]` 组成。把每个选项都当作独立字段，会让模型把同一份“性别”资料分配两次，触发重复来源校验。页面还使用没有 `for` 关联的相邻标签，因此必须区分问题标题与选项标题。

现在把同一表单所有者、同一名称且观察到同一问题和同一记录的原生单选合并为一个逻辑字段。模型看到问题标题和 `choiceOptions`，只选择一次资料路径。实际答案保留在本地，执行器再选择匹配的唯一选项。

选项节点与标题也属于执行身份。节点替换、选项增加或标签改变后，旧绑定不能继续使用。未命名、缺少问题证据或不同记录的控件不会仅凭相邻位置合并。普通复选框和声明仍交给人工。

这属于观察表示与工具设计。即使模型很强，也需要程序准确表达“问题”“选项”“经历记录”之间的关系。

## 3. 校验失败要回到模型，而不能被隐藏

规划输出必须符合工具 schema、来源白名单、记录索引和语义约束。失败时将错误代码、已知字段 ID、资料路径以及允许的格式诊断返回下一轮决策。现在还保留此前不同的规划错误，避免模型修复一处后忘记另一处。

执行记录增加分组规划进度和可展开的校验依据。不记录原始模型输出或资料值。给用户看的决策摘要说明当前选择的依据，不表示逐字展示模型的内部思考。

工具还要报告适配器类型和实际选项数量。`OPTION_UNAVAILABLE` 只说明没有唯一、可用的匹配项，不能被解释为菜单里没有选项。此次菜单含中英双语的学校就业网条目；补上明确的翻译与 BBS 附注识别后可正常选择，多个等价条目仍因歧义而保留原选项。

“个人简介”也不能回答与个人介绍无关的补充问题。此类问题需要独立资料或用户配置的该题答案；否则应明确保留空白。学习形式的合法最新教育投影则需保留其 `derivedFrom` 来源证据，不能因为路径经过投影就被误拒绝。

## 4. 死循环与逐步修正是两种情况

此前连续三次调用 `plan_fields` 就会触发重复动作停止，即使三次返回的是不同字段上的不同错误。现在重复保护同时比较动作参数和工具结果诊断。相同动作连续得到相同错误会停止；模型根据不同反馈修正时可以继续，仍受总步骤和写入预算限制。

程序没有为失败模型代选下一项填写工具，也没有悄悄切回原来的固定填写工作流。它改善观察和反馈，下一步仍由真实模型决定。

## 5. 成绩应分层表述

- 启动成功：原文档已绑定，本地服务已收到任务，观察结果已返回。
- 规划成功：模型的资料引用通过完整校验。
- 控件回读成功：当前 DOM 控件保留了本次写入或选中结果。
- 页面状态接受：有独立证据证明网站自身的业务状态接收了输入。
- 招聘服务器接受：需要保存、预览或提交后的独立证据。

此次调试没有执行保存、下一步或提交。自动检查使用虚构资料，真实验收使用正常 Chrome 工具栏入口和用户现有配置。实际覆盖及其限制单独记录在本次调试报告中。
