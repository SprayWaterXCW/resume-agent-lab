# 第 3 课：控件观察、缺失资料分类与人工补充

## 这一步在整体中的位置

当前主体仍是 `observe → decide → policy → execute → observe` 的模型决策循环。`LangGraph` 管理状态、边界和暂停位置；LLM 决定下一项工具。此次增强模型可以取得的证据，以及用户补充资料后如何恢复决策。

现在注册九种工具：`plan_fields`、`inspect_field`、`fill_field`、`retry_field`、`add_entry`、`audit`、`wait`、`request_review`、`finish`。没有按公司名称编排固定动作序列。校验失败直接返回模型，生产代码不会调用测试里的脚本决策替身。

[LangGraph 官方文档](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents)区分预定义的工作流路径与由模型决定过程和工具使用的 Agent。这里的状态图是执行容器；每轮工具选择属于模型。

## 1. 工具观察与填写分别承担什么

原来的观察报告已经包含字段标题、类型、选项和资料路径目录，但陌生控件失败后，模型缺少主动查询控件的办法。新增的 `inspect_field` 只接受当前快照和字段 ID，返回允许公开的选项文字、组件类型和组件 API 是否存在。

它不接受选择器、脚本或任意点击目标，不读取私有答案。模型可以根据查询结果决定填写、重试、继续别的字段或请求人工核对。每个逻辑控件在结构和资料版本不变时限制查询次数，避免把检查工具变成新的循环。

这借鉴 [Browser Use 的逐步动作循环](https://github.com/browser-use/browser-use/blob/914c59bdd4acd50e9628a97a96a3919313aebc85/browser_use/agent/service.py)：观察与执行结果是下一次决策的输入。本项目使用自建普通 Chrome 工具桥接，没有声称调用了 Browser Use Python SDK。

## 2. 为什么只读输入框不一定不可填写

`readonly` 有时表示必须通过选择器填写。地区控件通常同时包含显示地名的输入框和真正参与提交的隐藏 ID；日历也可能只允许通过自己的回调修改日期。把地名或日期直接写进显示框不能证明网站收到了合法字段。

这次增加两个受约束的组件适配器：

- 地区选择器：仅在观察到特定组件协议、相邻隐藏字段和网站自己的 `basSelect` API 时使用。沿真实字典逐层查找唯一条目，调用选择器内部的确认，再核对显示和隐藏 ID。ID 由网站选择器生成，执行器不编造。
- My97 日历：仅操作观察到的 `Wdate` 控件，使用网站加载的 `WdatePicker` 打开对应年月，核对日历标题后选择唯一日期。资料只保存年月时，不在未确认的情况下编造日。

组件行为来自当时页面公开加载的 [地区组件代码](https://stc.beisen.com/2025.05.30.001/cmsportal/skin/js/widgetnew.js)及 [日期选择器代码](https://smics.zhiye.com/Areas/Portal/Scripts/date_picker/WdatePicker.js)。代码按组件协议识别，没有按公司域名选择填写流程。页面加载未结束时仍可能已经存在这些组件 API；不存在或字典未加载时会返回具体失败代码。

这些适配器属于工具实现。模型只发出“用已确认的资料路径填写这个观察到的字段”，具体选择器协议由本地执行器负责。

### 组件函数存在，不等于组件已经可用

本次真实页面的 HTML 响应出现 `ERR_INCOMPLETE_CHUNKED_ENCODING`。表单大部分控件已经渲染，但页面一直 `loading`，地区组件依赖的 `BSGlobal.TenantId` 未初始化。直接调用已存在的 `basSelect` 会向 `/api/setting/undefined` 请求配置；该公共端点返回 HTTP 400，地区字典请求没有继续发出。

因此观察增加 `areaContextReady`，组件执行前核对原生初始化参数。缺失时返回 `PICKER_CONTEXT_NOT_READY`，不编造租户参数或打开无法加载的弹窗。模型可以依据这个反馈等待、检查其他控件或请求人工核对。这个限制来自实际组件协议，不是按公司的固定执行步骤。

真正打开的地区弹窗使用本轮随机标识绑定所有权，数据失败后只取消该弹窗。加载诊断仅保留设置、地区和拼音阶段的观察布尔值与请求数，不保存完整请求地址、租户 ID 或资料值。

## 3. 缺少资料与工具失败应如何区分

`fieldCoverage` 是逐项核对清单，不是动作计划。它结合当前字段、已验证映射、资料路径目录和执行回执，区分：

| 状态 | 证据与含义 |
| --- | --- |
| 尚未规划 | 未有合法映射，不能据此宣布资料缺失 |
| 缺少独立答案 | 规划明确报告缺失，且没有对应的已配置来源 |
| 已有资料，尚未核验写入 | 存在对应来源，但本轮尚未核验成功 |
| 执行失败 | 实际工具尝试返回失败代码 |
| 控件工具未完成 | 当前组件不支持或运行依赖没有就绪 |
| 页面控件尚未初始化 | API 存在，但原生初始化上下文缺失；不能误报缺资料 |
| 网页字典未加载 | 有资料且已尝试组件，但没有获得地区候选数据 |
| 日期需要确认 | 来源仅有年月，当前控件需要完整日期 |
| 来源需要核对 | 映射缺失、歧义或来源冲突 |
| 已有内容待核对 | 页面已有内容，但本轮没有证明其来源 |
| 本轮核验成功 | 有本轮回执，并保留最终复核结果 |

UI 会显示这些原因，并提供“补充本页缺失资料”。结构化问题跳到资料编辑器的独立字段，其他问题可以创建带原题的自定义问答草稿。草稿不含默认答案，用户保存后才成为可信资料。

健康史、保密协议等问题需要该题的明确答案。接受出差不能推出接受轮班；全职入职时间不能推出未来实习日期。两项看似相近的概念也应各自有资料来源。条件详情仅在适用时补充。

亲属任职也需要具体题目的答案，家庭成员或姓名不能证明其在某公司工作。年薪必须有独立年薪事实或明确年薪周期，不能直接借用未注明周期的金额。已确认的“是／否”工作意愿可以在本地转换为网页存在的“能／不能”成对选项；未知答案保持未知。

## 4. 人工参与如何成为 Agent 循环的一部分

模型可以选择 `request_review`。LangGraph 的 `interrupt()` 暂停当前运行，用户此时可以编辑资料，再用 `Command({ resume: "continue" })` 恢复同一运行。恢复后先重新观察原文档，再由模型决定下一步。[官方 interrupts 文档](https://docs.langchain.com/oss/javascript/langgraph/interrupts)说明了这一机制。

资料使用随机版本标识，版本改变时旧映射、旧尝试次数和旧核验结果失效。网页内容保留，但必须依据新资料重新规划和核验。版本标识不由私有值计算，模型和检查点不会收到简历原文或 API Key。

当前检查点使用 `MemorySaver`，支持本次服务进程中的暂停恢复。关闭或重启服务不会自动续跑旧任务；跨进程的数据库持久恢复仍是后续工作。

实测还发现：模型先请求人工补资料，策略要求先复核，模型复核后却选择结束任务。现在状态中保存一个简短的 `reviewIntent`，只记录模型自己的请求原因与步骤号。复核后模型仍能看到这个未解决的需求，再自行选择下一项工具。它不是系统自动插入的“复核后必定暂停”流程，也不保存私有推理或答案。

## 5. 选项等价必须有充分依据

之前的通用前缀比较会把“统招”匹配为“统招专升本”。文字包含关系无法证明概念等价。现在通用前后缀分数不足以触发选择；只有精确答案或明确等价转换可以选择。

色觉描述到是／否的转换只在特定问题表达、特定资料路径和明确事实值同时匹配时运行。未知或不愿透露不会被转换成否。等价转换在浏览器本地处理，不需要将健康答案发送给模型。

## 6. 如何验证与解释结果

虚构资料自动检查验证工具边界、选择器真实回调、隐藏 ID、日期精度、错误选项拒绝以及暂停后资料更新。模型替身检查 Agent 容器的行为，不代表真实 LLM 一定选择同样的动作。

真实验收必须从普通 Chrome 工具栏“开始填写此标签页”进入，使用用户原有资料和设置，不通过额外配置制造成功。控件回读、页面参与提交的字段状态、招聘服务器接受分别报告；没有保存或提交证据时，`serverAcceptance` 保持 `not_checked`。

## 7. 观察协议也是 Agent 的基础设施

0.1.6 出现了一次与模型决策无关的启动失败：补充年薪后，浏览器资料账本生成了 `salary_annual` 来源投影，而观察协议仍只有 `salary_monthly` 等旧类型。构建观察快照时，Zod 拒绝了这个新标记；模型尚未收到页面。浏览器又把未带错误码的原始异常折叠为 `CHROME_AGENT_FAILED`，执行记录无法显示真正的校验位置。

这说明工具调用 Agent 需要两类契约：一类是模型能选择哪些动作，另一类是执行器向模型提供什么合法观察。后者失败时，即使连接和模型设置正确，Agent 也无法开始决策。

0.1.7 将投影类型放到共享定义中，生成器和观察校验器使用同一份目录。同时按整份资料目录校验，保留具体条目索引。失败日志只保存阶段、异常类型、校验路径、规则和数量，不保存原异常消息、资料值或任意属性名。

回归检查从虚构资料导入开始，经过来源投影、观察构建、JSON 传输、服务再次校验，最后确认模型确实能开始决策。这覆盖了此前只检查“年薪投影已经生成”、却没有检查“投影能否进入 Agent”的缺口。工具基础设施修复不会改变生产环境中由模型选择下一步的控制方式。
