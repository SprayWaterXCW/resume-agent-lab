### 地区选择器的实际根因

正常刷新后，Chrome 再次报告主 HTML 请求 `ERR_INCOMPLETE_CHUNKED_ENCODING`，`document.readyState` 持续为 `loading`。大部分表单已经渲染，`basSelect` 函数也已存在，但 `BSGlobal` 只有 `Register`，没有原生地区组件依赖的 `TenantId`。

页面公开加载的 [widgetnew.js](https://stc.beisen.com/2025.05.30.001/cmsportal/skin/js/widgetnew.js)显示地区组件需要这个参数获取设置，然后才加载地区与拼音字典。浏览器实际出现的配置请求路径是 `/api/setting/undefined`；公开请求核对返回 HTTP 400，内容为无效请求。未观察到后续地区／拼音字典资源。

这份证据说明本轮不是“资料里没有籍贯”，也不是仅凭超时猜测网络不稳定。现有页面的初始化参数确实缺失；当前不能证明是哪一层网络或服务造成 HTML 截断。

现在 `inspect_field` 返回 `areaContextReady`，地区工具在原生参数缺失时立即反馈 `PICKER_CONTEXT_NOT_READY`。不会猜租户 ID、编造隐藏地区 ID、注入初始化全局变量或向显示框写入地名冒充选择成功。若页面自己的数据就绪，适配器再沿真实字典选择并验证原生回调产生的隐藏 ID。

### 不再把相近资料当成同一答案

- 亲属在某公司任职必须有该题的独立答案；个人姓名或家庭成员名字不能证明任职。
- 年薪只接受独立年薪事实或明确的年薪周期，不能借用未注明周期的金额。期望月薪不会自动乘 12 变成年薪。
- 接受轮班、无尘车间、岗位调剂分别保存；接受出差不能替代。
- 未来可实习日期不能借用过去实习经历日期或全职可入职日期。
- 条件详情匹配包含所属主问题，避免多个“请告知详情”串用。

## Agent 主线与恢复修复

当前循环仍为 `observe → decide → policy → execute → observe`。真实模型从九类工具中选择下一项动作。来源约束、控件就绪和文档身份检查限定工具合法性，没有按中芯国际编排填写顺序，也没有回退到旧插件的固定字段遍历。

第一轮 0.1.6 的真实执行 `6ef2639e-6dff-4c8c-b8ba-04789c28f34a` 同样复核了 20 项，但模型请求补资料被“先完成最终复核”拦下后，复核完选择直接结束，失去了可继续的暂停位置。这个结果推动了恢复修复。

状态现在保留模型自己未完成的 `reviewIntent`，仅包含请求原因和步骤号。复核后下一轮模型能看到该请求并自行决策。没有系统自动插入“复核后必须暂停”的业务步骤，也没有隐藏思维链或私人答案进入记忆。

最新真实执行最终选择了 `audit`，随后选择 `request_review`，Chrome 显示“Agent 已暂停，等待你核对”和“已核对，继续 Agent”。模型暂停后可以编辑并保存资料；资料版本改变会使旧计划与凭据失效，继续时重新观察、规划。暂停保存与恢复协议已有虚构资料自动检查；本次真实验收没有改动个人资料来制造恢复成绩。

## 自动检查与保留边界

- `npm test`：43 项通过，包含模型反馈循环、非法动作拒绝、过期文档、资料更新后恢复、控制台之外的 HTTP／WebSocket 工具契约、日期精度、原生选择器回调与隐藏 ID、失败弹窗所有权、缺少地区初始化上下文、亲属独立来源、年薪周期、条件问题归属、工作意愿选项和待核对请求记忆。
- `npm run build:extension`：通过，构建已用于最新 Chrome 实测。
- `npm run verify:baseline`：206 个稳定插件文件、0 修改。
- 组件自动检查采用虚构 DOM 和资料，不能证明真实页面缺失的地区字典已经加载成功。
- `MemorySaver` 只保留当前服务进程的暂停状态；重启服务不能恢复这次任务。
- 本轮没有招聘服务器保存或接收证据，不宣称服务器接受简历。

下一步应由用户补充独立答案，按需要启用已确认的日期精度规则，然后从原招聘页恢复或开始。地区页面初始化问题仍需网站真实加载恢复才能完成验收。后续 Agent 工程重点是减少反复全页规划的上下文成本、扩大跨布局评估、增加业务状态证据与持久恢复。
